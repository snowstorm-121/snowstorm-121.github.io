# “烛微观澜”项目案例设计

## 已确认的呈现方式

`/research/` 从四个空栏目改为两个已发布项目的总览：ScholarLens 与 RetailFlow。各项目有简述、实验状态、主要工作、案例页和 GitHub 原仓库链接；独立案例页分别位于 `/research/scholarlens/` 与 `/research/retailflow/`。案例页固定按“问题航标 → 工程舱图 → 实验潮汐 → 结论星屿”组织，提供原生章节锚点、返回总览及前往另一项目的链接。

沿用现有海岸书页的纸色与夜海阅读模式、同底色页眉、照片横幅、系统光标、可见键盘焦点和移动端竖排。只给研究页增加必要样式；主页外观、学习与生活页、PyTorch 笔记正文及既有公开 URL 不变。两个案例都是静态展示，不上线项目后端。

## 内容与证据

### ScholarLens

- 明确它是用户选定**单篇论文**范围内的本地 RAG 研究原型。说明 QASPER 正文与问答标注隔离、段落定位、BM25/Dense/RRF 检索、Top-5 原文上下文、本地 Qwen3 4B 回答、引用检查和审计记录。
- 复用项目仓库已跟踪的真实截图 `assets/scholarlens-demo.png`，标注“演示题不计入正式评测”；图片有替代文本且能按原比例自适应。
- 冻结 Test 的 300 道检索题中，EvidenceRecall@5 的分母仅为 240 道可回答题：BM25 0.4654、Dense 0.6290、RRF Hybrid 0.5901。该指标是证据覆盖，不是答案正确率。
- 冻结 100 题生成子集 Answer F1 0.3347；80 道可回答题有 22 道错误拒答，100 次输出有 9 次截断。用公开报告中的检索漏召、正确证据排第六而被 Top-5 排除、证据在 Top-1 仍拒答三个案例说明限制。
- 说明复用 Kotaemon 框架组件和 QASPER 数据/评测资源，突出本项目在论文数据定位、范围内检索、引用审计及冻结评测上的改造；链接仓库 `UPSTREAM.md` 和正式报告。不可把引用检查描述为事实正确保证，也不可宣称跨论文综合能力。

### RetailFlow

- 明确它是基于 LangGraph、Ollama 与 τ2 retail **模拟环境**的本地 CLI Agent 原型，不连接真实订单、支付或客服系统。
- 说明模型选工具，应用进行身份/订单归属校验，写入先形成绑定具体参数的提案；只有用户确认当前提案才写入。参数变化撤销旧确认，SQLite 同一事务保存业务状态与回执以供恢复和防本地重放。
- 提供与现有阅读主题匹配的静态 HTML/CSS 流程图，明确标注“流程示意”，不伪装成产品截图。真实跨进程取消订单演示应与无模型直接调用保护层的演示分清。
- 冻结评测 Dev 9 题与 Test 4 题，B0/B1/B2 各组分别为 Dev 0/9、Test 0/4。指出身份追问与工具协议失败；工程回归测试和单个成功演示不能代替模型业务成功率，也不证明通用安全或恢复收益。
- 标明 LangChain react-agent 和 τ2 retail 上游来源，链接 `UPSTREAM.md`、评测报告和演示记录；不可把整个项目说成原创或给未声明的项目整体许可证。
